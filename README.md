# Система автоматизации IT-поддержки первой линии на основе локальной языковой модели

Дипломный проект. Клиент-серверное веб-приложение: сотрудник задаёт вопрос в чате,
сервер находит релевантные фрагменты в базе знаний компании (RAG) и передаёт их
локальной LLM, которая формирует пошаговый ответ. Данные не покидают корпоративную
инфраструктуру.

## Архитектура

```
┌─────────────┐   HTTP/SSE   ┌──────────────────┐   Tailscale    ┌─────────────────┐
│   Браузер    │ ───────────► │  Сервер Node.js  │ ─────────────► │   LM Studio      │
│  (чат, адм.) │ ◄─────────── │  Express + RAG   │ ◄───────────── │   Qwen3 8B       │
└─────────────┘   стриминг   │  SQLite (БЗ+логи)│  OpenAI API    │   (машина с GPU) │
                              └──────────────────┘                └─────────────────┘
```

Компоненты:

- **Клиент** (`public/`) — чат для сотрудников и админ-панель базы знаний.
- **Сервер** (`server.js`, `lib/`) — Express-приложение: приём вопросов,
  лексический поиск по чанкам (RAG), сборка промта, проксирование стриминга
  ответа модели, журналирование обращений.
- **Хранилище** — SQLite (`data/helpdesk.db`): документы, чанки, журнал.
- **LLM** — LM Studio с моделью Qwen3 8B, доступ по OpenAI-совместимому API
  через защищённый Tailscale-туннель (WireGuard).

## Запуск

Требуется Node.js 18+.

```bash
npm install
cp .env.example .env        # указать адрес LM Studio и имя модели
npm run seed                # наполнить базу знаний стартовыми инструкциями
npm start                   # http://localhost:3000
```

На машине с GPU: запустить LM Studio → вкладка Local Server → загрузить модель →
Start Server (порт 1234) → в настройках сервера включить «Serve on Local Network»,
чтобы сервер слушал не только localhost. Адрес для `.env` — tailnet-IP машины
из панели Tailscale, например `http://100.101.102.103:1234/v1`.

## Как работает RAG (упрощённый, лексический)

1. При добавлении документ режется на чанки ~900 символов по границам абзацев.
2. Текст нормализуется: нижний регистр, ё→е, отсечение типовых русских окончаний
   («принтера/принтером» → «принтер»), удаление стоп-слов.
3. При вопросе чанки ранжируются по совпадению термов (TF с насыщением)
   с бонусом за совпадение с заголовком документа.
4. Топ-K чанков (по умолчанию 4) подставляются в системный промт модели вместе
   с правилами поведения (отвечать только по базе, при отсутствии ответа —
   направлять в IT-отдел).

Выбор лексического поиска вместо векторного — осознанный: для базы из десятков
инструкций он даёт сопоставимую точность, не требует модели эмбеддингов
(экономия VRAM) и полностью интерпретируем, что важно для анализа ошибок.

## Тестирование (глава 5)

```bash
npm start          # в одном терминале
npm run eval       # в другом
```

Скрипт прогоняет 24 тестовых вопроса (16 покрытых базой, 4 переформулировки,
4 вне базы) и сохраняет `eval-results.csv`. Ответы оцениваются вручную по шкале
0–2, метрики: доля решённых обращений, точность отказа на вопросах вне базы,
среднее время ответа. Журнал всех обращений также доступен в админ-панели.

## Структура проекта

```
├── server.js            # точка входа, API
├── lib/
│   ├── db.js            # SQLite: документы, чанки, журнал
│   ├── rag.js           # чанкинг, нормализация, поиск, сборка промта
│   └── llm.js           # клиент LM Studio (стриминг, health check)
├── public/
│   ├── index.html       # чат сотрудника
│   └── admin.html       # база знаний + журнал обращений
├── scripts/
│   ├── seed.js          # стартовая база знаний (8 инструкций)
│   └── evaluate.js      # прогон тестовых вопросов → CSV
└── data/                # helpdesk.db (создаётся автоматически)
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | /api/chat | Вопрос → SSE-стрим ответа (события: sources, token, done, error) |
| GET | /api/documents | Список документов базы знаний |
| POST | /api/documents | Добавить документ (title, category, content) |
| DELETE | /api/documents/:id | Удалить документ |
| GET | /api/logs | Журнал обращений |
| GET | /api/stats | Статистика (количество, среднее/мин/макс время) |
| GET | /api/health | Статус сервера и LLM |

## Отладка без GPU

Если машина с LM Studio недоступна, можно проверить всю систему на mock-сервере:

```bash
node scripts/mock-llm.js     # имитация LM Studio на порту 1234
npm start                    # в другом терминале
```

Mock отвечает заглушками, но позволяет отладить RAG, интерфейс и журналирование.
